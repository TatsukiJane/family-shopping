# Семейный список покупок (PWA)

Общий список «что закончилось» для семьи. Любой добавляет позицию, любой
отмечает купленное — все видят актуальное состояние. Открывают в двух
ситуациях: «вспомнил дома» и «стою у полки», обе решаются на главном экране
без навигации, в том числе оффлайн.

## Стек и команды

React 19 · Vite 8 · TypeScript 6 · Tailwind v4 · shadcn/ui · zustand · idb ·
vite-plugin-pwa · Vitest. Пакетный менеджер — **pnpm**.

```bash
pnpm install     # зависимости
pnpm dev         # дев-сервер: http://localhost:5173/family-shopping/
pnpm test        # Vitest, один прогон
pnpm test:watch  # Vitest в режиме наблюдения
pnpm typecheck   # tsc -b
pnpm lint        # oxlint
pnpm build       # tsc -b + vite build
pnpm preview     # отдать сборку и проверить PWA
pnpm icons       # перегенерировать PNG-иконки из public/favicon.svg
```

База пути одна для dev, preview и сборки — `/family-shopping/`. Запустить
с корня: `BASE_PATH=/ pnpm dev`.

Деплой — GitHub Actions на GitHub Pages при пуше в `main`
([.github/workflows/deploy.yml](.github/workflows/deploy.yml)).

## Архитектура: почему так

### GitHub как база данных

Данные — один JSON в приватном репозитории, читается и пишется через Contents
API. Ноль инфраструктуры, бесплатно, версионирование и откат из коробки, файл
читается глазами. Цена: нет реалтайма, нет транзакций, конфликты решает клиент.

### Два репозитория

| Что | Где | Почему |
|---|---|---|
| Код | **публичный** репо, GitHub Pages | Pages из приватного репо требует платный план, а сайт всё равно публичный |
| Данные | **приватный** репо, `data/list.json` | список покупок не должен индексироваться |

Токена в бандле нет, поэтому публичный код безопасен. Координаты репозитория
данных приходят на сборке из Actions **variables** (не secrets):
`VITE_DATA_OWNER`, `VITE_DATA_REPO`, `VITE_DATA_BRANCH`, `VITE_DATA_PATH`.
На устройстве их можно переопределить в настройках.

### Один общий токен, без PIN

Владелец выпускает один fine-grained PAT (Contents: Read and write, только на
репозиторий данных) и передаёт домашним. Остальным не нужен GitHub-аккаунт.

**Аутентификации в приложении нет.** Участник — это только подпись действий
(«добавил Айбек», «купила Айгуль»). PIN был в ТЗ §2.2, но его убрали: доступ
к списку даёт токен, а он лежит на устройстве владельца. PIN защищал бы от
того, от чего защищает блокировка телефона, и стоил бы экрана на каждом входе.

Практическое следствие: список видит каждый, у кого есть токен. Не храните
в нём ничего чувствительнее «купить творог».

### Синхронизация — item-level LWW

Локальный снапшот в IndexedDB — источник правды для интерфейса. Действие
применяется сразу (оптимистичный UI), кладётся в очередь и уезжает пушем.

```
push():
  remote = GET (cache: 'no-store')
  merged = merge(remote, local)          ← LWW по updatedAt
  merged ≡ remote → коммита нет, очередь чистим
  PUT merged со sha remote
    409/422 → перечитать и повторить, до 3 попыток, затем «ошибка»
```

Очередь **не переигрывается** при мерже: LWW делает мерж идемпотентным,
достаточно снапшота. Очередь нужна для счётчика «N изменений ждут» и чтобы
пережить перезагрузку вкладки.

Правила мержа ([src/lib/merge.ts](src/lib/merge.ts)):
- `items` и `members` объединяются по `id`, побеждает бо́льший `updatedAt`;
- `deletedAt` — обычное поле с меткой времени, а не удаление из массива;
- надгробия старше 30 дней вычищаются физически.

Триггеры: pull при старте, возврате фокуса и появлении сети; push с дебаунсом
2 сек. Поллинга по таймеру нет — это лишние запросы и лишние коммиты.

Ошибки различаются по коду и ведут в разные места ([src/lib/sync.ts](src/lib/sync.ts)):
`401/403` → `unauthorized`, чинится заменой токена; `404` → `missing`, чинится
правкой координат репозитория; `TypeError` → `offline`, чинить нечего. Текст
ответа GitHub едет третьим аргументом `onStatus` в `syncError` и показывается
в настройках: без него опечатка в пути и отозванный токен выглядят одинаково.
Любой успешный статус гасит этот текст.

## Отклонения от ТЗ

1. **PIN убран целиком** (ТЗ §2.2, §7, экран 2). Он не защищал данные, а стоил
   экрана на каждом входе. Участник остался как подпись действий.
2. **`updatedAt` у участника.** Схема ТЗ §5 его не предусматривает, но при
   self-service онбординге двое могут добавить себя одновременно — без метки
   времени такой конфликт не разрешить.
3. **Пуш отметки «куплено» ждёт 5 сек, а не 2.** Дебаунс — 2 сек, окно отмены —
   5 сек. Коммит через 2 сек отменялся бы вторым коммитом через три секунды.
4. **`display: standalone` и PNG-иконки.** В ТЗ не упомянуты, без них
   не проходит критерий установки на домашний экран.
5. **Секция «Куплено» живёт неделю, а не сутки** (ТЗ §7,
   [`BOUGHT_VISIBLE_MS`](src/lib/config.ts)). За сутки покупка уходила
   с экрана раньше, чем к ней возвращались после выходных. Это только
   видимость: позиция остаётся в файле, физически чистятся лишь надгробия
   старше 30 дней ([`TOMBSTONE_TTL_MS`](src/lib/merge.ts)).

## Интерфейсные тексты

Микрокопия follows редполитику навыка `sasha`:

- точку в конце коротких строк не ставим — ни в заголовках, ни в кнопках,
  ни в хинтах, ни в однострочных описаниях;
- кнопка — реплика пользователя («Проверить доступ», «Добавить», «Сохранить»),
  статус — реплика системы («Сохраняем», «Синхронизировано»);
- лейбл называет данные, а не действие: «Токен GitHub», а не «Введите токен»;
- ошибка говорит, что случилось и что делать: «Репозиторий не найден.
  Проверьте владельца и название», а не «Ошибка доступа»;
- одно состояние — одно название: нет «Готово» и «Синхронизировано» рядом.

Русские склонения по числу — через [`plural`](src/lib/plural.ts), включая
согласование глагола: «1 изменение ждёт», «2 изменения ждут».

## Подводные камни

- **`btoa` падает на кириллице.** Используйте [src/lib/b64.ts](src/lib/b64.ts):
  `TextEncoder` + порционный base64. На чтении Contents API отдаёт base64
  с переносами строк — их надо срезать до `atob`.
- **`GET` только с `cache: 'no-store'`.** Иначе браузер вернёт протухший `sha`
  и каждая запись словит конфликт.
- **`api.github.com` не должен попадать в Service Worker.** `runtimeCaching`
  в [vite.config.ts](vite.config.ts) намеренно пуст: SW кэширует только
  оболочку, данные идут через IndexedDB.
- **`404` на файле — не ошибка**, а сигнал «список ещё не создан». Экран
  настройки на нём строит self-service онбординг.
- **Метка времени локальной правки — `max(now, prev + 1)`**
  ([`nextStamp`](src/lib/ops.ts)). Часы на телефонах расходятся; без этого
  правка с отстающего устройства молча проиграет при мерже.
- **Классы цветов участников перечислены целиком** в
  [src/components/MemberDot.tsx](src/components/MemberDot.tsx). Tailwind
  сканирует исходники статически и не увидит класс, собранный из шаблона.
- **Соединение с IndexedDB надо закрывать в тестах** (`db.closeDb()`), иначе
  `deleteDatabase` блокируется и тест висит до таймаута.
- **`erasableSyntaxOnly` включён** — параметры-свойства в конструкторах
  (`constructor(private x: T)`) не компилируются.
- **`baseUrl` в tsconfig запрещён** в TypeScript 6; пути в `paths` резолвятся
  относительно самого tsconfig.
- **`base` одинаков для dev, preview и сборки.** Если в preview отдавать
  с корня, собранная страница ищет ассеты по `/<repo>/`, получает SPA-фолбэк
  вместо `sw.js` и манифеста — и PWA молча перестаёт устанавливаться, причём
  сама страница выглядит рабочей.
- **`test/setup.ts` лежит вне `src`.** У приложения браузерные типы без `node`,
  а `tsconfig.node.json` подключает `test` со своими. Внутри — одна строка
  `import 'fake-indexeddb/auto'`; WebCrypto не нужен, идентификаторы даёт `ulid`.
- **Источник Pages — только «GitHub Actions».** С «Deploy from a branch»
  `actions/deploy-pages` создаёт деплой и тут же получает `Deployment cancelled`,
  причём build остаётся зелёным и в логе нет ни слова о причине. Поэтому
  в [deploy.yml](.github/workflows/deploy.yml) стоит `configure-pages`
  с `enablement: true` — он переключает источник через API.
- **Не ставьте `timeout-minutes` на job деплоя.** У `deploy-pages` свой таймаут
  и внятная диагностика; внешний убивает шаг раньше и оставляет «cancelled».

## Структура

```
src/
  lib/        ядро: types, merge, sync, ops, github, db, b64, config, plural, utils
  store/      zustand-стор, склеивает движок синхронизации с UI
  components/ AddItemInput, ItemRow, BoughtSection, SyncIndicator, MemberDot
  components/ui/  shadcn
  screens/    SetupScreen, MainScreen, SettingsScreen, ItemActions
test/         setup для Vitest (fake-indexeddb), лежит вне src
scripts/      генерация иконок (sharp, запускается вручную)
```

Вся доменная схема — в [src/lib/types.ts](src/lib/types.ts): `ListDoc`, `Item`,
`Member`, `PendingOp`, `SyncStatus`, `RepoConfig`. PIN-экрана и `PinPad` нет,
см. «Отклонения от ТЗ» §1.

Тесты живут рядом с кодом (`*.test.ts`) и покрывают то, где ошибка не видна
глазами: мерж, операции, очередь и разрешение конфликтов.

## Первая настройка

1. Создать **приватный** репозиторий для данных (файл создаст само приложение).
2. Создать **публичный** репозиторий для кода, включить Pages с источником
   GitHub Actions.
3. В репозитории кода задать Actions variables `VITE_DATA_OWNER` и
   `VITE_DATA_REPO`.
4. Выпустить fine-grained PAT: доступ только к репозиторию данных, разрешение
   **Contents: Read and write**.
5. Открыть сайт, ввести токен, назвать себя. Остальные открывают ту же ссылку,
   вводят тот же токен и выбирают себя из списка.

## Границы MVP

Входит: добавление, отметка «куплено», переименование, удаление, оффлайн,
синхронизация, участники.

Не входит и почему: категории и сортировка по отделам (нужны от 30+ позиций),
количество и единицы (вписываются в название, отдельные поля замедляют ввод),
push-уведомления (требуют бэкенда), история и аналитика (есть история
коммитов), шаблоны (только когда список начнут вести регулярно).
